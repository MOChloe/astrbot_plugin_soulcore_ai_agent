# 能力说明

SoulCore 的能力围绕一个目标组织：让角色在长期交流中保持连续，同时把可见状态和控制入口留给用户。它不会把所有内部记录都堆进每次模型请求，也不会要求用户手动管理上下文窗口。

## 角色连续性

角色资料、说话方式、关系边界、当前处境和本轮真正相关的信息会在统一流程中组织。角色可以随着经历变化，但不会因为切换会话或聊天记录变长就自动丢失已经保存的身份与关系状态。

## 长期记忆与关系

SoulCore 会从真实交流中识别值得长期保留的经历，并把不同联系人的关系状态分开管理。不是每句话都会成为长期记忆；临时上下文、摘要和长期记忆承担不同职责。

用户可以在独立页面查看联系人、相处状态和已经保存的角色资料。底层数据库记录和内部任务标识不会直接暴露在玩家页面。

## 当前生活与主动联系

开启生活能力后，角色可以拥有聊天之外的地点、心情、近期事件和准备做的事。生活进展是单独维护的状态，不等于让模型在无人聊天时持续生成大量对话。

主动联系会结合联系人策略、安静时段、频率限制、当前状态和适配器投递能力决定是否发送。启用能力不代表角色会按固定间隔机械发言。

## 多轮行动

需要查询、生成或调用工具时，SoulCore 可以先完成多步行动，再把真实结果整理成角色的最终表达。内部计划、草稿和工具原始结果不会作为角色消息直接发送。

## 图片、语音与表情

- 视觉理解：在配置了可用视觉模型时理解收到的图片。
- 图片生成：在配置了生图模型并允许当前聊天发送图片时生成并投递图片。
- 语音：根据 AstrBot 与当前适配器提供的语音输入、输出能力参与交流。
- 表情：收集、理解和选择已配置的表情素材，让表达更符合当时情境。

媒体能力同时受模型、AstrBot 版本、适配器和当前聊天策略影响。某个模型支持图片，不等于所有适配器都能以相同形式收发图片。

## 模型与外部能力

主力文字模型是必需项。其他能力按需配置：

- 快速文字模型可以复用主力模型，用于轻量判断。
- 视觉模型只在需要理解图片时启用。
- 联网提供商只在需要实时查询或读取网页时启用。
- 生图模型只在需要生成图片时启用，并可能产生实际调用费用。
- 回复润色只处理最终表达，不负责改变角色的行动判断。

## 与其他插件共存

通过 AstrBot 标准注册指令调用的插件可以与 SoulCore 共存。SoulCore 会把这类指令和插件回复隔离在角色上下文之外。

会读取、改写会话上下文或同时介入普通对话链路的插件不在兼容范围内。两套记忆系统、上下文系统或自动回复系统同时处理同一普通消息时，无法保证输入顺序、状态与最终回复仍然一致。

## 数据与可见性

玩家页面默认只展示结论、实际状态和可执行设置。模型原始交换、解析过程与底层记录只在明确的开发或诊断入口中按需查看。进一步的数据职责划分见[数据边界](data-boundaries.md)。
