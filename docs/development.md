# 开发与检查

SoulCore 要求 Python 3.11 或更高版本。使用 `requirements-dev.txt` 安装运行与开发依赖。

插件自有运行代码统一通过 `from astrbot.api import logger` 获取宿主日志对象，
不自行创建 Python logging 或第三方日志实例。保留日志参数格式化、异常堆栈与
诊断附加字段；第三方 `_vendor` 源码保持原样，测试替身不进入发布包。

卸载与热重载测试必须覆盖仍有入站消息正在处理的场景。入站生命周期先关闭接纳，
给予已接纳任务 30 秒完成时间，再取消并等待剩余任务退出；应用层不得用同一截止时间
打断这个清理过程。入站任务退出后才继续关闭后台服务与数据库，所有清理成功后释放
运行锁。任何未完成的清理仍须保留运行锁，防止两个实例同时操作同一数据目录。
后台任务清理失败或超时时，数据库必须保持打开，供下次关闭尝试完成占用释放；
已成功的清理步骤不重复执行，全部依赖数据库的清理成功后才能关闭数据库。
回归测试须使用真实 SQLite 覆盖清理异常、超时及随后再次停用的场景。

页面读取通过官方 Page bridge 发起，单次读取最多等待 30 秒，超时在当前页面提供
明确原因和手动重试入口；迟到响应不得覆盖重试结果。该读取时限不应用于保存、
模型连接测试等写操作，也不自动重发请求。

设置读取与保存相互独立。刷新不得隐式提交草稿，也不得因为某个字段保存失败而阻止
生活资料等其他页面读取。读取返回时保留尚未保存区域的草稿、错误和并发版本；开始
读取之后发生的编辑或保存结果不得被迟到快照覆盖。编辑器重新挂载时使用同一份待保存
草稿；用户可以明确放弃当前区域修改后重新读取，其他区域的草稿继续保留。

群聊数值范围由 `GROUP_FLOW_INTEGER_LIMITS` 定义，并通过设置快照传给页面。
前后端都必须校验范围、整数和必填条件；服务端校验错误绑定具体字段，相关错误只在
所属区域显示。后台生活页面直接读取当前角色的背景推演开关，关闭时解释记录为何不再
自动更新；记录时间不代表后台任务发生故障。

联系人联系习惯自动保存期间，整组控件保持禁用，直到保存和版本快照刷新均完成。
测试须覆盖慢写入、慢回读和失败后重新编辑，确保连续操作不会使用同一份过期版本。

主 Core 的消息发生时间与模型请求时钟分别传入编译器：聊天行保留账本中的原始
时间，“当前时间”和相隔时长使用本次编译时的实时时钟。等待、延迟接纳和恢复后的
请求必须验证这两个时间仍然分离，不能把收信时刻重新标记为现在。

在 PowerShell 7 中运行唯一的本地检查入口：

```powershell
./scripts/check.ps1 -PythonPath <python.exe>
```

检查入口会把 Pytest、Python 临时文件统一写入项目内的 `.tmp/`。可通过
`-PytestBaseTemp <名称>` 指定 `.tmp/pytest/` 下的独立子目录；绝对路径也必须位于该
受管目录内。脚本和测试入口都会拒绝盘符根目录、用户目录或其他项目外路径，避免测试
产物污染外围文件系统。

使用 `-Full` 可额外执行浏览器冒烟测试和发布包验证。Node 只用于插件高级设置页面的开发与测试，插件运行不依赖 Node。

当前 mypy 门禁覆盖跨域 `contracts`、`shared` 公共内核，以及所有 feature 的
`domain.py` / `ports.py`。这些文件定义模块之间必须稳定的类型边界；实现层不得用
`ignore_errors` 掩盖问题，并继续接受 Ruff、架构契约和全量行为测试约束。类型覆盖范围
应随实现整理逐步扩大。

单独构建可直装 ZIP：

```powershell
<python.exe> scripts/build_release.py
```

发布包与公开 Git 提交树都必须少于 800 个文件。公开提交树的统计包含
`.github`、隐藏文件、文档和其他已提交文件，`export-ignore` 不会豁免它们。
发布前对独立公开仓库的待发布提交执行：

```powershell
<python.exe> scripts/build_release.py --public-repository <公开仓库路径> --revision <提交或树对象>
```

尚未提交的公开快照使用 `--public-snapshot <快照目录>` 检查全部实际文件；
此检查只排除根目录的 Git 管理数据，不应用插件安装载荷白名单。
