# SoulCore 数据边界

## 单一写入来源

这里的“来源”表示一个对象只能由一个业务边界写入，不表示聊天中存在事实权威等级或裁决法院。

| 数据 | 唯一写入边界 | 主要消费者 |
|---|---|---|
| 角色卡与开放的自定义 Prompt | 角色配置修订事务 | MainCore、需要角色身份的背景作者与媒体能力 |
| 世界种子、世界资料与创作边界 | 角色级世界配置事务 | 五位背景作者 |
| 平台聊天账本 | 入站接纳与 Outbox 送达结算 | MainCore 上下文、摘要、知识形成、普通帧前台连续性 |
| 入站语音接纳状态与转写结果 | 语音 admission 事务 | 入站幂等、崩溃恢复与有序账本写入 |
| 已完成 MainCore 行动结果 | MainCore 决策提交事务 | 普通帧前台连续性 |
| 背景实例与五位作者状态 | 背景初始化、配置或对应作者发布事务 | 调度器、对应作者、高级设置 |
| 不可变作者发布 | 对应作者发布事务 | 恢复、诊断、高级设置 |
| 隐藏故事模组正文 | 故事源发布事务 | 故事源、普通帧、关键帧、高级设置 |
| 角色生活时间线 | 普通帧或关键帧发布事务 | 当前视图、MainCore 生活投影、高级设置 |
| 角色当前七字段快照 | 普通帧或关键帧发布事务 | MainCore、关键帧、高级设置 |
| 表达 segment、可见 Outbox 与撤回动作 | MainCore 决策提交事务 | 持久投递、撤回执行与 Run 恢复 |
| 短命出站语音产物登记 | 语音投递准备与运行时清理事务 | 同一 Outbox 重试、OneBot `record` 运输与孤儿回收；个人微信无出站语音时不会生成产物 |
| 角色实例级表情停用 | MainCore 决策提交事务 | 表情检索、短引用解析与实例清理 |
| 正式 Memory 修订 | 知识形成事务 | MainCore 按时间装填的压缩历史正文、统一回想投影 |
| 会话 WorldInfo overlay | 知识形成事务 | 统一回想投影 |
| 回想文档、FTS、Embedding、关系边与场景 | Recall 索引 Outbox／后台 worker | 显式回想、生图前当前 WorldInfo 预取与管理实验室 |

作者摘要、MainCore 生活文本、高级设置页面和回想结果都是投影，不得反向成为第二份角色生活数据源。Embedding、关系边和场景同样只属于可重建索引。`RoleCurrentView.recent_experiences` 在读取时从时间线动态附加，不另行持久化事件正文。

角色自定义 Prompt 的正文与当前预设选择属于同一角色配置修订，但分别持久化：正文是可供模型读取的文本快照，预设选择是高级设置中的受校验 ID。MainCore、背景作者和其他 AI 运行时只读正文，不得写入或推断预设选择；页面加载也不得用新版预设正文是否逐字相等覆盖已经保存的选择。只有用户明确选择其他预设或直接编辑正文，才能在角色配置修订事务中改变当前选择。

## 角色包可移植边界

`.soulcore-role` 是角色配置唯一允许的玩家分享格式，但不是另一份运行中角色数据库。导出器从角色、世界与两类角色立绘的一致性快照生成稀疏补丁；导入器把补丁合并回当前已存在角色的原权威表，不创建第二套角色状态，也不创建或重命名 AstrBot 配置。角色修订仍是整包操作的幂等锚点，世界定义、世界资料、创作边界和立绘记录与它在同一 `BEGIN IMMEDIATE` 事务中提交。

允许离开本机的内容只有角色资料、对话参考、开放的自定义 Prompt、触发规则、世界定义、世界资料、创作边界，以及私聊／群聊各一张角色立绘。包内不保存 `profile_id`、`instance_id`、修订号、时间戳、存储路径、AstrBot Persona、模型／Provider／API 配置、密钥、开关、聊天、记忆、联系人、背景生活、任务、表情包、聊天图片或生成图片。清单中的标题只用于文件名和预览，不改变目标角色或 AstrBot 配置名称。

角色包中的 `{[character]}` 与 `{[User]}` 保留为跨环境身份模板。任何绑定具体群成员的平台身份标记都会在导出和导入边界被拒绝；错误只指出字段位置，不回显内部身份值。角色包没有远程资产语义，立绘必须是容器内已声明、已校验的原始字节，任何 URL 都不会被访问。

缺失字段表示保留目标当前值；出现的普通数组整体替换，显式空字符串或空数组表示清除允许为空的内容。`world.lore` 与 `world.boundaries` 只有出现时才整体替换。立绘缺失时保留，提供包内资产时替换，只有 `clear: true` 才删除。关系通信背景与故事创作边界属于必需 Prompt，显式空值会恢复当前版本系统默认，并在预览中说明。非默认 Prompt 按字面导入并将预设选择标记为 `custom`，不依赖导出版本的预设 ID。

预览只展示可读字段名称、当前／导入后摘要和必要完整文本，不展示原始 JSON、数据库身份、本地路径、包哈希、幂等键或锁令牌。确认令牌绑定目标 `role_ref`、角色修订、世界修订、两类立绘指纹和角色包哈希；任一目标内容在预览后变化都必须重新预览。新立绘先写入受管媒体存储并登记耐久清理保护，数据库事务失败时回收，成功后发布数据库备份、释放旧立绘并刷新背景世界种子。

`plugin_data` 中的主数据库是唯一当前数据源。数据根目录下的一致性快照不是自动接管主库的影子数据源：生产启动发现主库缺失时必须创建全新数据库并覆盖旧快照，不得把卸载或重装解释为恢复请求。只有调用方明确提供备份路径的受控恢复流程可以在主库缺失时激活对应快照。若已经存在“提交后备份失效”标记，主库缺失表示无法证明最新提交仍可恢复；启动必须失败关闭，既不能恢复旧快照，也不能用新空库覆盖这项数据丢失信号。

## 入站图片数据边界

入站图片组件的 URL、本地路径以及适配器生成的 `media_image_…` 名称都只属于当前事件的运输层，不是对方给图片起的名字。图片写入聊天账本时只保留媒体类型；只有真正的文件附件保留经过净化的可见文件名。图片字节、格式、帧数和存储路径由实例隔离的媒体资产持有，MainCore 当前轮接收有界视觉载荷，后续历史只接收媒体资产生成的视觉语义投影。上下文读取持久账本时也必须把带运输名的图片占位符当作同一图片位置清洗并替换，不能把内部名称投影给模型、摘要或知识形成。

视觉结果把“客观画面证据”和“交流观感”保持为两个字段。前者只写像素可确认的主体、动作、环境与正文；后者只在图片明显承担表情包、反应图或梗图的聊天表达时，概括图片稳定呈现的整体质感和通常交流效果。交流观感不是发送者当前意图，不能把“这张图常显得敷衍”改写成“对方此刻正在敷衍你”。历史投影只在交流观感存在时把它放在客观画面与 OCR 正文之间；普通照片、截图和信息图片保持事实优先。正式表情的结构化 metadata 保留原始客观画面与视觉交流观感用于审核，MainCore、检索结果和发送历史只使用不超过七十二字的社会语义优先释义，不额外倾倒标签。

## 语音数据边界

入站原音频不是 SoulCore 数据。它只允许在 AstrBot 事件仍有效时被读取，并可在受管临时区完成必要转码；无论成功、失败、取消或异常退出都不进入媒体资产、Prompt、工作记录、摘要、知识、备份或长期文件。正式聊天账本只保存按原组件顺序生成的 `（语音）转写文本`，识别失败时保存 `（语音）`。`inbound_voice_admissions` 只持久化角色／实例／平台消息 ID、状态、段数和安全转写文本，用于保证重复消息只调用一次 STT，并在重启后以空转写结算未完成项；表中没有源路径、URL、Base64、音频字节或音频哈希。

出站语音不是新的消息种类。MainCore 仍提交文字表达；`[[语音]]=是` 只形成内部 `presentation=VOICE`，要求投递器在平台支持时以语音替代文字。TTS 成功后，对话账本保存 `（语音）最终文字`；个人微信等平台明确不支持出站语音，以及 TTS、格式或明确的平台投递失败并降级成功时只保存普通文字。平台结果未知时不得再发文字，以免产生第二份可见表达。

生成音频只能作为同一 Outbox 的短命投递产物存在。运行时清理账本登记受管路径和到期边界，让安全重试复用同一 WAV，并在成功、失败、取消、打断、送达未知、过期或孤儿回收时删除。实际 OneBot v11 `record` 的 Base64 只在运输调用内生成，不写数据库或日志；工作记录只保留 Provider、模型、格式、时长、字节数、文字长度、状态和有限降级原因，不保存音频、Base64、路径、URL或音频哈希。

## 回复润色只读边界

ResponsePolish 只在既有“回复润色”开关开启时读取三类材料：MainCore 已提交的原始表达、最后一个已接受终止轮次的工具外模型可见原文，以及原表达已有留话。工具外原文不是 Provider 隐藏 reasoning；被拒绝轮次和更早轮次不能混入本批回复。

工具外原文与留话只构成一次润色请求的瞬时投影，经过请求级身份引用转换与 XML 转义后发送给现有润色 Provider。MainCore Agent 的真实请求、原始响应和执行结果仍按工作记录边界保存；这份润色投影本身不另写数据库、对话账本或摘要。两类材料共享独立 2,048 Token 预算，各先取得一半并转让未使用余额，超长时分别保留首尾；模型窗口不足时先删除整个内部投影，再按既有规则裁剪近期对话。关闭润色时不生成投影。

原始表达是可见内容的唯一来源。最终轮工具外的模型可见原文只能辅助理解已经做出的取舍和关系姿态，留话只能帮助避免破坏发送后的连续性；仅存在于辅助区块的事实、计划、解释和未采用方案不能进入输出。润色可以重写句式、合并重复意思、移除无新信息的口头外壳和非必要专业过程，但不能借近期对话或说话风格重新筛选原始表达已经选中的独立信息；删除后会使对方少知道一件原文明确说出的新事情时，必须换一种说法继续承载。润色协议物理移除留话字段，模型不能生成或修改留话；代码在校验可见结构后按原消息位置恢复原值。长文本复制检查会拒绝照搬仅见于辅助区块的内容，任何材料缺失、越界、解析失败或 Provider 故障都沿用 MainCore 原文。

## 主动联系证据边界

主动联系时取得的生活时间线事件、已完成行动结果、证据类型、后台帧来源和证据时间，只用于机会判定、预约、前台接管与最终结算。它们可以继续存在于调度器的冻结快照和 MainCore 请求元数据中，以维持重启恢复、幂等与 CAS 栅栏；但不得传入 `ConversationContextService`，也不得形成 MainCore 的上下文来源或 Prompt 区块。

MainCore 决定是否开口以及谈什么时，只读取正常的角色语义上下文：角色现在、已生活经历、人生方向、仍在考虑的打算、对话历史和按需回想。调度器选择“此刻可以主动联系”的内部依据不自动成为角色必须提及的话题，更不能把 `ORDINARY`、`KEYFRAME`、发生时间、预约编号或结算状态投影给模型。

## Timer 生命周期证据边界

MainCore 不判断定时器是否应继续，也不新增对应 Prompt 或命令。成功提交后，它只通过不可展示的 `CommittedCoreRunEvidence` 返回最终被接受轮次的工具外模型可见原文、决策类别、输出状态和版本栅栏；被拒绝轮次、行动结果和 Provider 隐藏 reasoning 不进入这份证据。Timer 运行层把证据与定时器描述、来源消息共同冻结到 `timer_lifecycle_reviews`，再交给没有人物设定和社交风格的独立分类请求。三类材料都按不可信输入转义，模型可见原文最多占 2,048 Token，完整上下文不超过 4,096 Token。

审查器只能返回两个保留结论或两个完结结论。证据缺失、沉默、一次无回复、歧义、非法输出、超时、模型不可用和未配置都不能结束规则；长期约定默认保留。完结必须在事务内重新核对规则仍为活动且版本未变、本次 occurrence 已成功、没有更新 occurrence 开始、审查期间没有新前台活动。任一栅栏变化只把审查记为失效，不修改规则；应用成功只软完结规则并取消未来未开始 occurrence，本次已提交消息不撤回。Prompt、原始模型输出和枚举解析进入 AI 工作记录，高级设置只展示聚合结论，不暴露证据 JSON、内部 ID、任务或幂等键。

## 身份与实例隔离

`profile_id` 是角色档案边界；`profile_id + instance_id` 是一条聊天世界线边界。

角色级共享：

- 角色卡与开放的自定义 Prompt；
- 世界种子与起初约定的人生方向；
- 世界资料；
- 创作边界；
- 默认背景模型与角色级模型配置。

实例级隔离：

- 聊天账本和 MainCore 运行；
- 背景实例与五位作者状态；
- 不可变作者发布；
- 隐藏故事模组；
- 角色生活时间线和当前视图；
- 角色实例级表情停用状态；
- 前台消息／运行游标；
- 调度、任务代次、前台租约和失败状态。

现实聊天联系人与虚构世界人物不是同一实体。联系人更像角色在异世界认识的网友，不在角色现场，也不拥有修改角色世界的权限。角色创建者配置的世界种子是明确的创作输入；聊天中随口说“国王死了”只是一次联系人表达，两者不能混为同一种来源。

背景作者 DTO 中的 `participant_id` 只作为请求内查找键，平台 ID 和数据库 ID 永不投影给模型。冻结候选里实际出现的现实参与者统一映射为 `P1/P2…`，角色本人固定为 `C`；同一映射服务身份目录、对话人物字段、可信身份素材与作者输出解码。显示名只帮助阅读，同名参与者仍保持不同 P 引用。没有稳定 `participant_id` 的现实消息不能按显示名降级，直接从作者素材中排除并写诊断。

私聊的模型可见显示名默认按“平台可读昵称 → 当前联系人设置称呼 → `对方`”单向退化；开启当前私聊的“始终使用这个称呼”后，优先级改为“设置称呼 → 平台可读昵称 → `对方`”。设置称呼是管理员为当前联系人提供的展示配置，不是平台事实、用户声明或虚构人物身份；它只进入身份目录和相应对话人物字段。默认模式下，后续观察到真实平台昵称时立即以真实昵称为准，通用的“对方”等占位值不得反向覆盖已保存的真实昵称；强制模式则在当前消息、历史对话及相关身份资料中统一使用设置称呼。群聊不读取这项私聊配置。

## 前台与后台的排他时间线

同一实例的 MainCore 与背景作者绝不并行生活。

前台入站接纳、缓冲／群窗口交接和 MainCore 执行使用引用计数的前台租约。第一项前台工作建立租约代次；重叠工作共享同一 token 并增加计数。取得租约的事务会提升连续性版本、取消排队背景任务，并请求取消已经运行的背景作者；同进程任务管理器随后立即停止匹配执行器，并在确认 Provider／执行协程退出后才允许 MainCore 继续。

所有前台引用释放后才清空租约。租约有效期间：

- 背景任务不能被领取或开始；
- 已冻结草案不能发布；
- 硬到期只保留为待运行条件，不能抢占前台。

前台开始不会改写任何作者的 `next_due_at`、`hard_due_at` 或普通帧累计；如果已有背景任务，它只会失效并保留原到期债务。最后一项前台工作结束后，READY 实例需连续安静 60 秒才能重新物化到期背景任务。

普通帧输入的 `BackgroundFrameInterval` 是“上次成功推进时间 → 本次作者输入冻结时间”的唯一连续区间，聊天发生的时间也在其中。离线、重启或连续聊天不会切出多个待补区间；到期时只生成一个压缩普通帧。关键帧同样只能写入自己冻结的连续过去窗口。帧结尾必须自然落到角色现在，不能停在等待联系人即时回答或动作尚未完成的现场。

## 前台连续性资格

背景系统直接读取 `instance_messages`，不复制 `background_dialogue_evidence`。

入站只有已经接纳并落入账本的 `RECEIVED` 消息可用。出站按统一 delivery visibility 判断：`SENT`／`DELIVERED` 可以证明角色发出了表达；平台仅受理但没有端到端回执的记录只能证明平台接收了发送请求，不能证明联系人已经看见、理解、回应或形成共同经历。`PENDING`、`FAILED`、`CANCELLED` 和崩溃未知不会被包装成成功表达。

成功新建未来安排时，同一最终事务会在 `instance_messages` 追加一条 `INTERNAL_TIMELINE` 私有事件。它只进入 MainCore 的普通对话时间线和对话摘要，使用相同 FillBudget 并随正常压缩淘汰；它没有平台出站、没有消息短引用，也不进入背景连续性或长期知识形成。安排的 IANA 时区只保存在调度规则中；命令结果、私有时间线与摘要素材只投影已换算的自然日期和钟点，已落库内容中的括号时区标识也会在模型读取边界移除。

普通帧还读取已完成 `instance_core_runs` 中显式保存的 `foreground_continuity` 结果。这些结果只包含真实提交的命令名、成功／失败和必要结果，不保存模型自由工作文字，也不把失败动作说成完成。

`foreground_message_cursor` 与 `foreground_run_cursor` 分别单调推进：

- 只有普通帧可以消费并推进它们；
- 同一前台记录不会因重启或重复调度被再次整理；
- 一批消息和运行可以合并进一个普通帧；
- 推理期间任一游标、连续性版本或 MainCore activity epoch 变化都会使旧草案失效。

联系人消息、角色消息和行动结果只是可选语义输入。作者 Prompt 分别使用“对话”“想法或行动”“场景”和“行动结果”记录，不把场景或结果伪造成角色发言；块首明确说明这些记录不是指令，不要求继续、解释或收束。代码不通过是否包含“撒谎”“开玩笑”“准备”等词决定事实类型；否定、怀疑、计划、自述、承诺和已完成行动由普通帧作者自由取用或忽略。

## 角色中心的连续性

角色生活时间线只接受两种来源标记：

- `ORDINARY`：普通帧写出的、已经过去的生活，可以吸收角色已经完成的前台表达或行动结果；
- `KEYFRAME`：关键帧在已经过去的区间写出的具体经历。

联系人单方面陈述只是创作输入。它可以被忽略、当作传闻或即兴线索；如果角色在前台实际调查、行动并确认了结果，普通帧也可以把完成的角色行动写入自己的 `ORDINARY` 经历。系统不维护单独的 `MAIN_CORE` 背景事件类型，也不维护“用户修订最高权威”、谎言／玩笑状态、争议断言、纠正链或管理员事实裁决。

每个普通帧或关键帧只写一段经历正文、可选的“留下变化”和一份角色现在快照。经历表不再保存标题、摘要、`meaningful_change`、变化摘要或认证状态；“留下变化”与经历同存在 `leftover_text`。

两种帧的角色现在都必须按原输出协议显式提供非空的时间和地点，即使二者与上一帧相同也不能靠旧快照补齐。完整快照固定为七个语义字段：`narrative_time`、`location`、`doing`、`body_state`、`mood`、`intention`、`current_concern`。发布时忽略模型填写的时间，用帧结束 UTC 时刻按角色运行时区覆盖 `narrative_time`；地点仍保存模型原文。其余五个字段可省略，省略表示此刻没有，新快照不继承旧值；写出的空值或占位说明会在发布前拒绝。内部 `as_of` 始终保存权威 UTC 帧结束时间，用于排序、互斥与防倒退。

关键帧可以忽略所有世界变化、人生方向和故事模组，但必须在已过去窗口内写出一个具体场面、互动或小情节。它不复核或认证旧经历的重要性。

故事源模组、世界变化状态和人生方向状态是创作材料，不是角色必须逐字维护的已知事实。故事源保存不可变模组正文、真实曝光计数和 PENDING／ACTIVE／CONCLUDED 历史状态；经历—模组关联另存在关联表中。ACTIVE 只表示曾有角色交集，不表示进行中或必须继续。普通帧与关键帧可以取用，也可以始终忽略。

## 可见性矩阵

五位作者按职责读取白名单数据：

- 世界变化作者读取世界种子、世界资料、创作边界和自己的状态；不读取角色现场、聊天或生活时间线。
- 人生方向作者读取角色投影、当前视图、近期生活时间线、自己的状态及可选世界变化参考。
- 故事源作者读取角色投影、当前视图、自己的状态、既有故事模组及可选世界／人生方向参考；模组仍必须在角色介入前独立成立。

五位背景作者共用同一条不可裁剪的现实聊天人物边界：现实聊天中的对方和群成员只提供已经发生的交流，不属于背景创作空间。作者可以写角色收到消息后的自身反应，但不得替现实聊天人物新增台词、行动、到场、身份、经历、关系、想法或情绪，也不得把约定、玩笑或设想写成这些人随后参与了角色的背景生活。可继续创作的参与者仅限角色本人、角色世界既有人物和新创造的虚构人物。
- 普通帧作者读取角色投影、连续帧区间、自己的状态、当前视图、近期生活时间线、故事模组、可选上层状态，以及成功游标之后尚未消费的前台消息／运行结果。
- 关键帧作者读取角色投影、已经过去的可写区间、当前视图、近期生活时间线、故事模组与可选上层状态；它不消费前台游标。

参考作者状态和故事模组只是可选输入，不构成必须执行、续写或收束的任务。作者不能读取另一作者的原始输出、任务租约或版本内部数据。

近期经历对所有生活相关作者仍按冻结时间线从新到旧展示，但执行权限不同：人生方向作者可以阅读经历及仍有效的变化正文，却不看到 `Vn`；只有普通帧和关键帧能输出 `<留下变化已解决>`，也只有尚未解决且确有变化的经历显示 V 标签。序号先按冻结位置分配，已解决、无变化或预算裁掉的记录不显示标签也不压缩后续序号；解析严格绑定最终请求真实可见的精确标签。

MainCore 可以取得结构化角色当前视图、有界近期亲历、完整人生方向、世界变化和统一排序前十二个故事候选；预算内跳过无法完整装入的候选并最多展示两个。每个故事候选把模组正文与最多三条关联经历保持为同一个裁剪和曝光单元；模型文档用“别处”放正文，仅在有关联经历时用“你在场时——”分隔。背景稳定引用、生命周期状态、距离、供给分数、作者原始输出、调度和版本字段不能进入 MainCore Prompt。需要更早角色经历时，只能通过统一“回想”查询已发布的角色生活时间线；故事模组仍不进入事实召回域。

聊天联系人只看到角色通过正常发送协议实际发出的消息。后台生活不会自动投递；角色可以在 MainCore 中依据当前关系和话题自行选择是否讲述已经生活过的经历。用户可以在受控的高级设置中检查作者、模组和时间线，但支持报告和普通聊天都不暴露私有材料。

## Recall 回想边界

背景系统不再维护世界实体、断言、关系、认识状态、谓词基数、争议或修订图谱。`background_world_entities`、`background_world_assertions`、`background_world_relations` 及其修订／纠正表已退出当前 Schema。

产品级回想合并以下只读来源：

1. 原始可见消息、正式 Memory／WorldInfo 修订；
2. 角色当前状态与已经生活过的时间线；
3. 带成员范围的会话摘要，以及从上述证据建立的可重建场景与关系索引。

隐藏 GM 模组、五位作者私有状态、未公开消息、撤回修订和跨实例资料在 Repository 查询边界上即不可达。图和场景只扩展候选，最终返回必须落回权威修订或原始证据。回想为空时明确拒答，不能伪称检索到了事实；它也不取消 MainCore 在既有角色和世界边界内进行前台即兴、行动和创作的自主权。

MainCore 首次推理不从 Recall 索引自动预取。正常 FillBudget 通过专用只读投影直接取得活动 Memory 的发生时间、`brief`、可选 `ultra_brief` 与去重所需来源消息号；模型正文只显示时间和 `brief`，其余字段只用于本地裁切或去重。记录严格按时间从新向旧装填，不能用关键词、相似度、重要度或当前查询改写顺序。

普通图片生成在最终画面方案冻结后，以该方案及本轮已确认的画面事实预取当前实例的 `WORLD_INFO/CURRENT`；只把 Recall 安全渲染后的高置信结果放入生图世界事实层，不读取普通 Memory、历史修订或其他实例资料。该终端预取不调用 Recall 推理模型；统一预取允许最多 30 秒完成本地索引读取，以兼容低配部署，无命中时保持原生图流程，真正超时或检索异常只记录可观测降级。

## 原子事务

以下操作保持各自原子：

- MainCore 结果、表达批次、输入批次／群窗口结算与 Outbox 写入；
- MainCore 显式暂离与同轮最终决策；Timer 对暂离的结束和已保留消息领取；
- 平台账本的入站接纳、出站送达和撤回结算；
- 前台租约取得／续租／释放及背景任务失效；
- 背景作者发布；
- 当前实例背景重建；
- 输入缓冲、群聊窗口、知识批次、文件成果和运行清理。

背景发布的共同部分在一个短事务中提交作者状态、不可变发布、输入版本快照、调度、任务代次和失败清理。按作者类型再附加：

- 普通帧写 `ORDINARY` 经历、可选 `leftover_text`、七字段当前快照并推进两个前台游标；
- 关键帧写 `KEYFRAME` 经历、可选 `leftover_text` 和七字段当前快照；
- 故事源只新增模组正文；普通帧与关键帧可选登记经历—模组关联或了结。关联、状态迁移、新交集曝光清零与经历保存同事务提交，同帧介入并了结时以了结为准。

模型推理不占用发布事务。草案携带配置、连续性、activity epoch、时间线、当前视图、发布、作者状态和参考作者状态版本；任务 ID、generation、前台租约和初始化步骤也必须仍匹配。任一依赖变化时比较交换失败，草案不得部分提交或覆盖新现实。

MainCore 的一个可见表达 segment 以 `(profile_id, instance_id, source_run_id, segment_index)` 唯一定位。`segment_index` 和 `output_count` 必须非空且非负；`output_count` 只统计可见发送，因此只有撤回动作的 segment 合法地为 0。表达批次行、完整有序步骤、可见 Outbox、撤回动作、表情停用意图和 Run 结算在同一事务提交，任何形状、顺序、延迟、引用或数量校验失败都会使整次提交回滚。

玩家消息打断表达批次时，投递层继续持久化完整的尝试、取消和恢复证据，但 RolePlay 层不读取这份运维说明。已经进入发送边界的表达只使用原有对话账本记录；明确取消且未发出的表达在读取时投影为打断消息之前的普通本人对话项，仅标明“被打断，未发出”。这些投影和普通对话共用 `CURRENT_DIALOGUE` 的 FillBudget、时间顺序、累计摘要与清理边界，不建立第二套 Prompt 区块或独立配额。

“暂离”只属于一个真实聊天实例的前台消息门禁，不是角色生活事实、Timer、未来安排或背景作者任务。门禁策略默认关闭且由管理员拥有；关闭时指令和相关说明都不进入 MainCore Prompt。开启后也只接受 MainCore 明确提交的原因与唯一未来时刻，不从自然语言状态、沉默、背景帧或 `<角色现在>` 推断。暂离结束说明只随取得现场所有权的一轮投影一次：延期批次、自然到期生命周期唤醒、恰时前台入站或 Timer 打断四者互斥，不会叠加第二轮；成功交接或结算后清除。平台 ID、租约、generation、activity epoch、批次引用和内部原因码仍只留在服务端。五位背景作者没有读取这份快照的端口。

消息回合判断与“暂离”是不同边界。前者只拿当前入站批次，以及批次之前按账本顺序倒取、再恢复为正序的最多四条可见对话；可见出站只接受本人已经成功或可能成功送达的消息。投影只含 `C/Pn` 人物引用、纯文字、相邻时间差和受控媒体类别，不含显示名、平台身份、完整组件、URL、路径、资产 ID、角色资料、摘要或更早历史。近期对话超过动态输入预算时从最旧端移除，当前批次不因附加前文被挤出。

`sticker_instance_item_states` 只覆盖一个角色实例对一个共享表情项的可见性，不修改或删除 `sticker_items`。实例运行时重置会清除这层覆盖，即使保留可用表情库存；角色级运行时清理会清除该角色全部实例的覆盖。删除角色实例或共享表情项时，相应覆盖由外键级联删除；仅重建背景生活不触碰表情停用状态。

## 调度边界

MainCore 故事曝光的提交边界位于成功模型调用之后、模型命令解析之前。`background_story_run_exposures` 以 `(run_id, story_source_id)` 去重，只在首次插入时递增故事的 `shown_count`；最终决策事务不再拥有第二条曝光结算链路。失败调用不写账，已成功调用的曝光不会因本轮后续失败或取消而回滚。

五位作者拥有独立调度和模型覆盖。同一实例一次至多运行一位背景作者，不同实例继续受全局后台并发限制。

普通帧、故事源、人生方向和世界变化按各自区间安排下一次运行。关键帧由普通帧计数和最长间隔触发。上层作者状态不是一套隐式提前唤醒协议，也不能制造下层执行义务。

角色级 `background_life_enabled` 与 `background_life_version` 是背景生活唯一的运行开关和版本。它统一决定该角色全部好友与群聊是否继续生成、是否向聊天模型投影背景生活；实例不再保存第二份启停状态。快速引导在一个事务中核对角色版本与世界修订，更新这份开关、`world_definitions.life_direction` 和现有实例的运行门禁；新的开局想法只复制到尚未初始化的实例，已经发生的经历与已经开始的实例不被重写。相同配置重复提交不增加版本。

关闭背景创作会停止新的作者任务，并让整份背景生活投影退出 MainCore Prompt；对话账本、MainCore 结果和角色已经生活过的当前视图／时间线仍然保留在本地。恢复后从当前边界继续，不按错过的每个周期连续补跑。

租约、任务代次、作者 generation、发布唯一键和输入版本栅栏共同保证重启、重复领取与并发 worker 不会重复发布。前台中断的背景任务正常取消并可由调度器基于当前状态重新物化，不作为需要人工恢复的创作失败。

## 初始化与重建

新实例在开始时冻结开篇锚点 `T`，并在完成以下五个作者步骤前保持 `INITIALIZING`：

1. `WORLD`
2. `LIFE_DIRECTION`
3. `STORY_SOURCE`
4. `KEYFRAME`
5. `ORDINARY`

世界、人生方向、故事模组和关键帧可以按创作需要自由回看，但不需要补齐连续历史；关键帧把具体情节交接到 `T−6h`，普通帧只发布 `[T−6h, T]`。随后进入 `READY`。锚点、关键帧交接和每一步都持久化，重启后从未完成步骤继续，初始化不回放聊天来伪造旧背景生活。

私聊中触发初始化的首条真实消息写入聊天账本，但保持知识不可见且不投影为背景前台素材；它以持久延后批次跨越初始化，只有 `READY` 后才原样进入 MainCore。群聊触发消息不建立这份重放批次。异常中断若留下孤立的私聊初始化消息，恢复器只按确定的初始化来源重建同一个幂等批次。

“重建当前背景”删除目标实例的作者产出、故事模组、背景生活时间线和当前视图，重置调度与版本并提升任务代次。角色卡、世界种子、世界资料、创作边界、聊天、知识和记忆保留。前台消息／运行游标移动到重建时的当前尾部，因此不会把旧聊天重新写成新背景作品。

旧租约、旧草案和迟到模型响应不能在新 generation 回写。初始化完成提示与实例 `READY` 结算保持同一事务边界。

## Schema 升级边界

1.x 数据库从正式 schema version 1 开始拥有连续、不可变的发布身份。1.0 以前的 revision、列复制清单和运行时补值逻辑不属于发布边界；这类未知结构只允许管理员显式归档后重建。已发布身份之间则必须保留全部仍受当前业务契约拥有的数据，安装新版本不能把清库、角色重建或后台状态重置当作升级步骤。

每次结构变化必须同时新增目标身份和唯一前向迁移。需要数据变换时，变换与 DDL 位于同一数据库事务，由明确的源字段和目标字段定义；不得在正常启动、低频恢复器或业务读取端长期保留“顺便回填”的第二条升级路径。单次定时器只由 occurrence 成功结算事务软完结，角色 Prompt 选择只读取已保存的当前字段，玩家资料证据只接受带明确类型的当前形状。

迁移前快照、迁移事务和最终滚动备份都属于同一升级生命周期。快照失败时不开始迁移；任一步失败时回滚整个版本链；完整性、外键或精确身份检查失败时不发布新备份。来自更高版本或迁移失败的数据库不会进入清空界面。显式“重建当前背景”仍只是一项用户发起的实例业务操作，不是插件升级手段，也不改变数据库 schema 版本。

主数据库、WAL／SHM、运行锁、迁移快照、滚动备份、文件制品、恢复目录和包含凭据的恢复 ZIP 都属于同一私密数据边界。任何文件或锁出现以前先收紧数据目录；多级目录逐级创建并立即收紧，现存符号链接或 Windows junction 一律拒绝。POSIX 目录／文件分别为 `0700`／`0600`；Windows 路径禁止继承，只保留当前 TokenUser 的 FullControl，并把对象 Owner 同时设为该 SID。临时文件、发布后的目标及既有受管备份都执行相同检查。

事务提交与滚动备份发布是两个不同的事实。提交完成后备份失败不能把已经生效的业务操作向调用方报告为“未执行”；系统保留成功结果、记录可观测告警，并先耐久发布失效标记再移除可能陈旧的快照。并发取消也必须等待这项不可取消的失效处理后再原样抛出。下一次成功且通过校验的备份发布后才清除标记。

## 作者工作集与模型窗口

作者输入使用职责白名单和有界近期切片，而不是世界图谱或创作节点索引。当前实现分别限制近期生活事件、故事模组、未消费前台消息、已完成前台运行结果和世界资料的数量；这些上限只定义来源工作集，不保证任意模型都能装入。

一次运行先冻结完整白名单投影。候选素材涉及的现实参与者先统一分配临时完整身份目录并预留最大 Token 成本，再计算作者固定 Prompt、不可裁内容、预留输出和安全余量的真实最低窗口，从正式路由淘汰装不下的模型。剩余窗口才用于装入可选记录；可选内容只按完整区块、完整记录或完整字段移除。全部裁切完成后，目录只保留最终非目录载荷中真实幸存的 P 引用与完整身份标记，P 编号不压缩，没有现实参与者时整个目录省略，并重新断言最终请求没有超窗。

角色投影、当前视图、过去帧时间和输出合同不能被静默截断。所有候选都无法容纳必需内容时，本次任务以不可重试的上下文预算错误终止。预算、裁剪日志、路由元数据和内部错误码只进入诊断，不进入作者 Prompt。

## 管理接口与秘密

背景读取统一通过 `background_workspace`，写操作统一通过 `background_action`。所有写操作携带 `expected_version`；版本冲突返回对应设置或操作旁的可读错误。

默认页面按“当前生活、五层作者、故事模组、经历时间线、运行设置”组织，不展示数据库主键、租约 token、幂等键、内部枚举或原始 JSON。真实 Prompt、模型原始输出、解析结果和提交阶段通过 AI 工作记录查看。

平台身份、访问凭据、数据库路径、作者私有状态、隐藏模组秘密和任务内部字段不得出现在普通聊天或脱敏支持报告中。
